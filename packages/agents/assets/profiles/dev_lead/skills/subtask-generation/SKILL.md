# subtask-generation

## When to Use
研发负责人从需求 PRD + 验收标准生成子任务时。

## Procedure
1. **读输入**：需求 PRD + 验收标准 + 已有子任务（避免重复）+ 项目代码现状（判断紧耦合度）。
2. **按独立闭环边界生成草稿**：每个子任务可独立开发、独立验证、独立关闭；标注 `typeLabel`（前端/后端/全栈/联调）与 `dependsOn`。
3. **自检合并条件**：前后端小且紧耦合且无并行收益 -> 合并全栈单任务。否则保持拆分（上游优先：后端 API/数据/权限/迁移为上游）。
4. **展示草稿给用户确认（HARD-GATE）**：禁止未经确认创建任务。
5. **确认后调用** `ai_devflow_propose_task` 产出 `AiTaskProposal[]`。
6. **输出拆分报告**：子任务清单（标题/类型/dependsOn/闭环说明）、合并决策记录、依赖链说明。

## 合并判定（同时满足才合并）
- 围绕同一交付紧耦合；
- 规模一人一 worktree 可端到端交付；
- 拆开任一侧都无法独立验证；
- 无并行收益。

## Pitfalls
- **过度拆分**：一个字段改动拆成前后端两碎片（应合并全栈）。
- **拆分不足**：把不相关模块塞一个巨任务。
- **依赖错标**：漏标 `dependsOn` 导致并发启动前置未完成的任务；或循环依赖（由 `validateProposalDag` 拦截）。
- **绕过 HARD-GATE**：未确认就产出任务。
